# MuseFlow AI Studio - 系统重构设计规格书

> 日期：2026-06-02  
> 状态：待评审 (Pending Review by GPT-5.5-mini)  
> 背景：将现有的 `ai-photo-template-miniapp` 完全重构为桌面端优先的创作者工作台。

## 1. 系统定位
**MuseFlow AI Studio**：一个集 提示词创作、ChatGPT 生图、Agnes 视频生成、佳作收藏管理 于一体的创作者工作台（Creator Workbench）。核心亮点是**创作资产管理系统**的闭环。

## 2. 核心架构与 UI 布局 (三栏一底)

### 2.1 左侧：佳作收藏栏 (Assets & Favorites)
- **定位**：灵感与资产的沉淀区。
- **功能**：按项目分组（人像、海报、视频等），支持多维标签（电影感、写实等）。
- **数据保留**：每项保留原始提示词、模型、尺寸、种子、生成时间、视频转化状态。
- **交互**：支持一键收起为窄边图标栏。

### 2.2 中间：AI 工作区 (The "Brain")
- **定位**：AI 创意导演与对话控制台。
- **布局**：
  - **顶部**：当前项目标题 + 模式切换（灵感模式、精修模式、批量模式、视频模式）。
  - **中部**：AI 对话流（输出创意描述、中英提示词、正负面提示、构图光影建议）。
  - **底部**：提示词编辑器（供用户手动微调）。

### 2.3 右侧：展示与结果管理区 (Gallery & Results)
- **定位**：生成结果的可视化与闭环操作区。
- **功能**：Masonry 瀑布流展示图片/视频。包含生成中状态、失败重试。
- **卡片交互**：缩略图 + 标题 + 标签，按钮组（收藏、放大、复用提示词、转视频、下载、多图对比）。

### 2.4 底部：全局生成配置栏 (Generation Console)
- **定位**：高频参数快捷调整台。
- **配置项**：
  - **模块**：模型（GPT Image / 备用）、数量（1/2/4/8）、尺寸（1:1/4:5/16:9等）、清晰度。
  - **风格**：强度（保守/平衡/大胆）、参考图上传（人物/场景等）。
  - **视频**：是否调用 Agnes、时长、镜头动作幅度。

## 3. 核心工作流 (Core Workflows)
1. **文生图闭环**：用户输入创意 -> AI 拆解输出 Prompt -> 调整底部参数 -> GPT生图 -> 右侧展示 -> 满意收藏至左侧。
2. **佳作优化闭环**：点击左侧收藏 -> 中间加载 Prompt -> AI 分析并给出变体 (V2/V3) -> 右侧对比展示。
3. **图生视频闭环**：右侧图片点击“转视频” -> 中间 AI 生成 Agnes Prompt -> 底部设置镜头 -> 视频区展示。

## 4. 技术栈调整方案 (Tech Stack Refactoring)
从现有的（原生JS+代理端）迁移到现代化全栈桌面优先架构：
- **前端 (Frontend)**：`Next.js` (React), `Tailwind CSS`, `Shadcn UI` (组件库), `Zustand` (本地 UI 状态), `TanStack Query` (服务状态), `Masonry`。
- **后端 (Backend)**：`FastAPI` 架构。
- **数据库 (Database)**：采用开启 `WAL` 模式的高性能 **`SQLite`**，抛弃外部重型数据库，满足单人极速本地读写。
- **基础设施**：不使用 Docker/Redis。采用 Python 原生的 `asyncio.Queue` 构建单进程异步生图队列，降低系统资源开销。通过内置 WebSockets 引擎提供实时反馈。

## 5. 核心数据库模型 (Schema Design)
重构引入以下核心表关系：
- `projects`: 项目集合（如“秋季海报专案”）。
- `assets`: 媒体实体，区分 image/video，绑定 R2/OSS URL。
- `prompts`: 提示词快照，包含系统模板与用户输入。
- `favorites`: 收藏夹关联。
- `generation_jobs`: 异步任务队列表，记录任务状态（pending, processing, success, failed）。
- `tags`: 多对多关联的资产标签。

## 6. 实施策略 (Phased Implementation)
因涉及完全重构，建议按以下阶段实施：
- **Phase 1: 基础设施改造**：初始化 Next.js 前端结构，集成 Shadcn UI，设计三栏布局 Shell。更新 FastAPI 的数据库 Schema。
- **Phase 2: 核心流打通**：实现中间对话区与 GPT API 对接，底部参数栏状态绑定（Zustand），生成任务投递。
- **Phase 3: 资产管理闭环**：实现右侧瀑布流展示，落库逻辑，以及左侧收藏夹管理。
- **Phase 4: 进阶模式与视频**：实现图生视频 (Agnes) 接入，多图对比，本地 IndexedDB 缓存优化。
