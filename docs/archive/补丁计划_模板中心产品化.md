# 补丁计划 — 模板中心产品化

## 一、目标

完成模板中心核心功能闭环：搜索、分类筛选、收藏、最近使用。保持 mock 模式，不接入真 API。

## 二、背景

模板库已达 54 个 / 11 分类，无搜索筛选时用户发现成本过高。需在现有底座（Round 1-8 已完成后端搜索 API、埋点系统、价格标签）之上，补齐前端体验层缺口。

## 三、改动拆轮（每轮 ≤3 文件）

### Round 1：前端搜索接入后端 API（1 个文件）

| 文件 | 改动 |
|------|------|
| `public/app.js` | `renderTemplateList()` 重构为 async；关键词搜索调后端 `/templates/search`；输入 debounce 400ms；分类筛选保持本地过滤 |

**详细步骤**：
1. `renderTemplateList()` 改为 async 函数
2. `state.searchQuery` 非空时，调 `GET /templates/search?q=&page=1&limit=100`
3. 输入事件加 400ms debounce，停止输入后才调后端
4. 所有 `renderTemplateList()` 调用点加 `await`

**验收标准**：
- 输入"古风"→400ms 后列表刷新为 6 条结果
- 切换分类→即时本地过滤
- `npm run check` 零错误

**回滚策略**：恢复 `renderTemplateList()` 为同步函数，回退到本地过滤逻辑

---

### Round 2：模板中心快捷入口 + 最近使用后端接口（3 个文件）

| 文件 | 改动 |
|------|------|
| `public/index.html` | 搜索框下方新增快捷入口 DOM：🔥 热门 / ⭐ 收藏 / 🕐 最近 |
| `backend/routers/templates.py` | 新增 `/templates/recently-used`（基于 `UserEvent` 表查询最近交互模板） |
| `public/app.js` | `renderQuickFilters()` + 三种快捷过滤模式；搜索/分类时自动清除快捷入口 |

**详细步骤**：
1. HTML 插入 `.quick-filters` 容器
2. 后端新增 `recently_used_templates()`，查过去 30 天 click/generate/batch_generate 事件
3. 前端渲染三个按钮，点击后设置 `state.quickFilter`，调对应接口

**验收标准**：
- 点击"🔥 热门"→显示推荐模板
- 点击"⭐ 收藏"→只显示已收藏模板
- 点击"🕐 最近"→显示最近交互模板（无数据时为空列表）
- 搜索时快捷入口自动取消选中

**回滚策略**：删除 HTML 中的 `.quick-filters`，回退 `app.js` 到无快捷入口版本

---

### Round 3：生成埋点修复 + 模板 tags 补全（2 个文件）

| 文件 | 改动 |
|------|------|
| `public/app.js` | `generateFromTemplate()` 中补充 `trackEvent('generate', { template_id: templateId })` |
| `scripts/enrich_templates.py` | **新建**：基于 category/style/scene/clothing 自动为 54 个模板生成 `tags` 数组，写回 JSON |

**详细步骤**：
1. 在生成成功回调中插入埋点上报
2. 脚本读取每个模板 JSON，提取关键词生成 `tags`（如古风→["古风", "美女", "写真"]）
3. 写回文件，验证 JSON 格式正确

**验收标准**：
- 单次生成后数据库出现 `event_type='generate'` 记录
- 运行脚本后，抽查 3 个模板有 `tags` 字段且语义合理
- `npm run list` 加载 54 模板零报错

**回滚策略**：恢复 `app.js` 删除埋点行；脚本不执行则 tags 保持原状
